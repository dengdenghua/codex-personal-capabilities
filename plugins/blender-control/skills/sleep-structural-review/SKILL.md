# 智能睡眠产品结构评审

按本项目“床边温控主机＋循环水路＋柔性水垫＋传感控制”组织评审。类似Eight Sleep只描述架构方向，不借用竞品参数、获证信息或医疗宣称。保留现有专项的技术方法，本skill负责选取检查范围、处理跨专项关联并统一结果。

## 开始与阶段判断

记录产品/配置、目标市场/用途/用户、单/双区、制冷方式、电源、开闭式水路、液体配方、床垫/床架组合；模型、图纸、BOM、固件、样机及报告版本。未知项明确标出，不据旧光学项目或渲染外观推定。

读取 [阶段与专项路由](references/stage-routing.md)。采用用户项目的阶段定义，EVT/DVT/PVT仅是默认工作映射，不是标准要求。用户没说阶段时，根据现有材料选择临时阶段并写依据；只有概念模型时做概念/详细设计预审，不默认已有样机或完成验证。阶段名和资料成熟度冲突时报告差距，继续能做的工作。

先列本次拟检查的专项和项目ID范围，再顺序读取相应SKILL及必要的checklist/basis/验证计划。综合评审遍历14个专项的适用性，逐项标“本次审查/已有证据沿用/未覆盖/不适用（理由）”，不必加载所有细节；不可因为资料缺失把安全相关项写成不适用。单项请求保持其范围，仅补必要的关联检查。

## 统一判定与风险

读取 [问题、风险与关闭规则](references/risk-and-closure.md)。依据S?/S/E/批准项目文件、证据状态、问题状态、风险等级四个维度分开，不把“缺资料”变成“不合规”，也不把“未发现问题”变成“已验证通过”。标准版本、条款和核对范围沿用专项，未读正文不升级为已核标准。总入口不另外发明数值要求。

风险R1–R4为本skill的工程排序建议，使用项目已有分级时以其为准并给映射。依据可信失效链、后果和暴露评估；不虚构概率或RPN，不用低发生频率淡化严重人身风险。证据不足而涉及潜在严重后果的项记“暂定R1/R2＋待确认”，说明缺失证据，不能直接说已证实危险。

## 评审与汇总

1. 优先核水路压力/泄漏和水垫载荷边界，再查温控故障、凝露及电气传播，同时核冷热端能量边界。其他专项按阶段与实际风险展开。
2. 检查模型时遵守相应CAD控制skill，识别精确文档/配置/单位。仅建立评审框架不启动CAD、不自动修改模型。改模型须有任务授权并遵循工作副本规则。
3. 保留原专项ID（HY/WP/TC/CD/NV/FH/FS/CS/ST/TO/AS/TH/THS/DF及安规ID），分配稳定问题编号ISS-001等。同一对象/场景/失效链合并为一条主问题并保留所有来源ID；不同措施或验收标准的失效不要强行合并。
4. 统一编号REQ-001（要求）、EVD-001（证据）、TST-001（试验）。有旧台账时沿用ID，不重排。共享试验可关联多个问题，但分别给各验收项结果；不能因一个泄漏试验通过就关闭疲劳、卫生或湿态电气问题。
5. 每条整改说明对象/措施、关联设计变更和复测范围；闭环须有同配置/版本的证据及残余风险评估。旧试验是否可沿用需给变更影响依据。

## 输出

使用 [统一评审报告模板](assets/review-report-template.md)。默认直接在回复中按模板给出结果；用户要求文件时保存到指定项目位置，不改写模板为某项目台账。至少输出：阶段与范围、覆盖矩阵、问题清单（按风险排序）、试验待办、阶段推进建议及未覆盖范围。可只展示关键行，但实际未检/待确认不得消失。

试验待办须有问题/要求关联、目的、版本、方法来源、工况/样本量/时长及其依据、仪器、验收准则、停止条件、责任与期限；未知值明确待定，不自行生成安全温压或寿命门槛。只做计划时状态为待计划/待执行，不写已试验。故障/极限验证用台架和模拟负荷，不在睡眠人体上验证危险边界。

阶段结论只给工程建议（可进入下一步/有条件推进/建议暂缓/资料不足），写明范围与条件；不代替设计负责人批准、整机认证、开模/量产放行。未完成试验和安全证据不能以项目进度或问题总数少为理由忽略。
