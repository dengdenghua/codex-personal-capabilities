# Bounded receivers, coordinates and output lifecycle

Use `lt_resource_status` before full-model saves and large traces. Its RAM and disk values are distinct; it does not measure VRAM or predict the application's allocation peak. Save reserve defaults are operational safeguards, not a model-size estimate. Increase `required_free_bytes` for known larger models. Keep task-specific retention manifests; automatic pre-replacement backups carry identity/hash sidecars but are not pruned by age/count.

Use `lt_receiver_inventory` to distinguish defined, enabled, saving and path-collecting receivers. `lt_configure_receivers` defaults to at most two selected names, disables all other forward collectors, and reads back settings. DMD-only optimization normally needs one. Raising the configurable cap requires a justified diagnostic batch. It does not delete definitions, clear caches, alter backward analyses or turn off global simulation path collection; inspect those settings separately.

After scaling/moving geometry, use `lt_validate_receiver_planes` with physical target frames and minimum ranges derived from the current model. Its checks apply to dummy planes; a full-sphere surface origin may be its curvature centre while its receiver uses a tangent origin. Euler triples are not unique. Do not move a curved-surface receiver just because XYZ or Euler numbers differ. It validates supplied targets, not their optical meaning. First establish medium, normal, surface identity and local-to-global transformation with a few native rays.

Save receiver frames, model units, physical evaluation plane, apertures and source denominator with every export. Distinguish a DMD texture base, nominal facet-centre plane, tilted microfacet hit and offset air-space monitor. Project each ray with its own direction; do not assume the monitor coincides with the device or silently copy coordinates from a prior scaled version. Use the correct local propagation sign; do not fold returning rays into incident illumination.

`lt_ray_trace` now checks enabled sources, receiver cap and a configurable free-RAM floor. Supply the selected forward simulation key and `expected_rays` to reject early-ended runs. The command still runs all enabled simulations; inspect other simulations before using it. A completed COM call and a nonempty old mesh do not prove the intended run finished. The count check does not establish statistical convergence or power closure.

`lt_export_receiver_rays` writes a new CSV in batches of at most 5000 rows with a coordinate/seed/count/SHA256 manifest. It rejects invalid shapes, nonfinite values and changed counts/seeds/view. Failure leaves `complete:false` evidence. No full ray array or path-string array is returned in the tool response. A cache can still be stale before export; bind it to a known completed trace and unchanged geometry.

Only after every required receiver's output has been verified, use the documented `FlushSavedRayDataMemory` command. It clears saved rays for all receivers, so one successful export alone does not authorize discarding unexported receivers. Never clear a user's intervening trace or unsaved analysis. Close only known task-owned idle views; do not close a model as a shortcut for closing one view.
