# 模型保留与清理清单

在首次完整模型保存时登记原始输入、当前结果及回退用途。参数扫描优先保存设置、差异、随机种子与结果；全模型只在有恢复或交付用途的节点保存。预估下一次输出与临时峰值，空间不足时先减少可再生数据或清理已核实的旧文件，不通过降低验收要求处理。

`scripts/retention.py` 默认只预览；传 `--apply --journal <新绝对路径>` 才删除。只接受明确列出的任务自有、已被验证结果替代的普通文件；验证全部路径、保留文件 SHA256 和替代证据后才开始。拒绝链接、越界、保留目标、缺失替代依据及哈希变化。途中失败留下逐文件进度。不会按名称、日期或“最新 N 份”删除。

清单契约：

```json
{
  "schema": "engineering.retention.v1",
  "root": "<任务绝对目录>",
  "retain": [{"path":"<保留文件绝对路径>","sha256":"<实测 SHA256>","reason":"当前验证结果","validated":true,"validation_evidence":"<实际验证记录绝对路径>"}],
  "remove": [{"path":"<旧生成文件绝对路径>","sha256":"<实测 SHA256>","role":"superseded_generated","task_owned":true,"reason":"具体替代关系","superseded_by":"<上述保留文件绝对路径>"}]
}
```

`validated` 是执行者基于真实证据作出的分类，工具检查路径和指纹，不证明光学验收。仅“文件非空”不能支持将未知历史成果分类为已被替代。原始输入和有独立用途的实验对照应保留。用户明确授权范围及项目已有保留策略优先。

每次阶段交付同时记录：全模型数量及总字节数、保留用途、删除清单或不能删除的具体原因、RAM 与磁盘实测值。不要把“已读技能”或“移入同盘归档目录”当作清理完成。
