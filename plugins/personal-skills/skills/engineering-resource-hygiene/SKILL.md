# 工程资源与残留管理

将资源管理纳入工程过程：完成一阶段，就检查是否可以释放上一阶段资源；不要等到内存耗尽或磁盘堆满才处理。配合当前工程专项技能使用，不改变用户的任务目标。

## 分清资源，先测再优化

- 分别关注运行内存 RAM、显存 VRAM 和磁盘空间。删除旧文件主要释放磁盘，不能据此声称内存已下降；压缩归档仍占磁盘，也不等于清理。
- 资源密集任务开始前，检查相关进程、可用内存、已有应用实例和工作目录的主要生成物。优先读取轻量指标，不为盘点而递归扫描整台电脑或加载全部文件。
- 在大型模型载入、批量计算、渲染、重复迭代后，以及任务交付前复查。普通小改动无需反复全量盘点。
- 对比阶段前后的实际占用和增长趋势。若可用资源持续下降、重复操作后占用不回落、出现换页或分配失败，先停止增加任务并定位来源，再继续。不要仅凭单次高占用认定泄漏。

## 执行时主动控制峰值

- 优先复用已连接的正确应用实例和会话；避免每次尝试都新开 CAD、仿真软件、浏览器或后台服务。确需多个实例时，按资源容量限制并发，遵守专项工具的单实例约束。
- 大数据优先流式读取、分块处理、分页查询；避免同时保留多个等价数据副本、大数组、整套图像或重复网格。预览使用足够判断的分辨率，最终输出再使用目标精度。
- 阶段完成后关闭本任务已不再使用的文档、分析窗口、渲染上下文、文件句柄、连接和临时会话；释放可控的大对象引用，使用工具支持的缓存释放机制。
- 垃圾回收、清空缓存或重启应用只能解决相应问题，不作为每一步的固定操作；不要为降低显示数值而反复强制回收或清空系统工作集。
- 多次运行后仍持续增长时，检查重复载入、对象引用、事件订阅、连接和子进程生命周期。修复可控的资源释放路径；必须重启时先保存并确认可恢复，再正常退出本任务实例。

## 控制文件与版本增长

全模型保存及阶段清理时，读取 [保留清单与执行工具](references/retention-manifest.md)。先登记替代关系和验证证据，使用明确文件清单预览及清理；不得以文件日期或最新数量上限代替归属判断。收尾必须给清理结果或具体保留理由，不以“已读取本技能”代替执行。

- 优先沿用工程现有目录和版本管理方式。当前工作成果使用稳定名称；可再生的中间文件集中在明确的任务临时目录，避免散落到源文件旁。
- 不因每次修改就复制整个项目，也不无限生成 v2、v3、final-final 等副本。只保存有用途的里程碑；版本控制已覆盖的文本修改通常无需再整份备份。
- 对本任务创建且可确认用途的生成物，默认保留当前已验证成果，以及有实际恢复价值的最近一个可用回退版本；用户要求、工程追溯、原始数据和既有保留策略优先。该默认不授权删减既有历史档案。
- 新结果保存成功、能重新打开或通过相应检查后，再清理已被取代且没有独立用途的本任务副本、失败导出、临时截图、解包目录和中间缓存。不要让备份目录成为另一处无限堆积点。
- 仍在运行或待排障的失败任务应保留必要日志与证据；问题解决后只留下有诊断价值的内容，不无限保留整套重复输出。

## 清理边界

- 先确认归属、用途、依赖和恢复方式。可自主清理本任务产生、已失效且可安全再生的临时内容；历史文件、未知归属缓存、用户会话、原始输入和未保存成果不能只因“看起来旧”就删除或关闭。
- 版本号、修改时间和文件名不能单独证明可以删除。用户要求清理旧版时，先识别当前有效版本与必要依赖，再限定清理范围。
- 结束进程前核对准确 PID、实例及其承载文档；优先正常关闭。不得按进程名批量结束应用，不得中止其他任务或用户正在使用的会话。
- 删除前解析绝对路径，确认目标位于指定工作区或明确的任务临时目录；拒绝空路径、根目录、越界路径及指向范围外的链接。Windows 文件操作使用同一 shell 的原生命令和 LiteralPath，不跨 shell 拼接删除命令。
- 不全局清空系统临时目录、共享缓存、安装依赖、驱动缓存或其他项目。对有恢复需求的旧成果优先采用既有回收机制；把文件移动到另一个文件夹不算释放磁盘。
- 不把编写本技能当作立即清理当前机器的授权。对不明归属且不可安全再生的内容，保留并说明具体待确认项；不要为常规任务临时文件的安全清理增加无必要的确认流程。

## 收尾验证与汇报

- 交付前确认最终成果有效、引用和依赖完整、必要回退可用；释放本任务闲置资源，清理已验证无用的生成物。
- 只报告实际完成的操作。测得数据时，分别简述内存、显存或磁盘变化；未测量就不宣称释放了多少资源。
- 说明仍保留的必要进程、文件或未解决增长问题及其原因。后续迭代复用当前成果，继续执行阶段检查，避免重新积累相同残留。
